# API 版本与限流治理

> 文档编号：`c50-it-api` · 领域：it · 语料：corpus-50 · 锚点令牌：`C50-029-API`

## 1. 目的与适用范围

本制度规定经统一 API 网关对外与对内开放的接口之版本兼容策略、废弃节奏与租户级限流配额，适用于开放平台、合作方集成及被网关托管的业务服务。客户端 SDK 发版须与本制度废弃窗口对齐。服务网格内部东西方调用另有配额登记，但不豁免破坏性变更的公告义务。

## 2. 基本原则

- **兼容优先**：破坏性变更须给调用方迁移窗口，禁止无公告突然切断。
- **配额公平**：默认租户共享基线配额；超限可申请提额并按平台计费或合约执行。
- **契约先行**：OpenAPI / Proto / 错误码语义变更进评审，禁止文档外「软破坏」。
- **可观测**：按版本统计流量、成功率、429 比例，并开放给租户 Owner 看板。

## 3. 核心规定（检索锚点）

1. 破坏性变更须保留旧主版本至少 90 天；默认租户 QPS 配额 120。
2. 本制度检索锚点令牌为 `C50-029-API`，用于评测与抽检，不得删除或改写。
3. 与生产变更窗口制度交叉时，网关路由切换与大流量切流仍须落在常规或紧急变更窗口。

## 4. 版本与破坏性变更

- 主版本号递增表示破坏性变更：删除/重命名字段、新增必填、改变鉴权或幂等语义、改变成功/错误码含义。
- **破坏性变更须保留旧主版本至少 90 天**：自新主版本对默认流量全量之日起算；并行期内须提供迁移指南、字段对照与示例。
- 90 日内若旧版错误率异常或头部客户未完成迁移，架构师可批准延长保留并备案，不得无声缩短。
- 兼容变更（新增可选字段、新增接口、放宽校验）可走次版本，无需 90 天双版本，但仍须变更单与文档同步。

## 5. 限流与租户配额

| 项 | 规则 |
|----|------|
| 默认租户 | **QPS 配额 120**（网关按 `tenantId` 聚合；允许短时突发约 1.5 倍，超出仍计 429） |
| 超限响应 | 返回 HTTP 429，携带 `Retry-After`；禁止静默丢弃或只记日志不返回 |
| 提额 | 业务提交峰值证明与成本承担方；平台审批。临时提额 ≤7 天，到期自动回落 |
| 内部服务 | 网格配额单独登记，不占用开放平台默认 120，但须防止打满下游 |

针对恶意刷取的安全封禁由安全策略执行，与正常提额流程分离。

## 6. 废弃、下线与通知

废弃公告须含替代接口、对照表、联系人与计划下线日。到期前 14 天、7 天、1 天向调用方 Owner 发送三次提醒；到期后网关返回明确下线错误码与文档链接。禁止仅在变更群口口相传代替公告。

## 7. 沙箱与压测

沙箱环境配额单独配置，原则上不高于生产默认的 2 倍，数据必须脱敏。禁止使用生产密钥对沙箱压测流量反打生产集群；跨环境密钥混用一经发现立即吊销。

## 8. 禁止事项

禁止无公告缩短旧主版本保留期、对个别租户私下关闭限流导致「隐形特权」、在文档外增加隐藏必填头造成软破坏性变更、用重试打满邻居租户配额。

## 9. 常见问题

- **问：破坏性变更旧主版本保留多久？** 答：须保留旧主版本至少 90 天。
- **问：默认租户 QPS 多少？** 答：默认租户 QPS 配额 120。
- **问：超限返回什么？** 答：HTTP 429 并带 `Retry-After`，不得静默丢弃。

- **问：兼容变更要不要公告？** 答：要同步文档与变更单，但不必保留 90 天双主版本。

## 10. 相关系统与表单

- 系统：API 网关版本路由、租户配额中心、开发者公告与 429 看板。
- 表单：破坏性变更评审、迁移指南、提额申请、废弃下线公告。
- 对接：星轨变更窗口、SDK 发版日历、安全封禁策略。沙箱与生产密钥严禁混用，违者立即吊销。

## 11. 附则

本制度由平台架构组解释；默认 QPS 数值调整须产品、架构与 SRE 联席通过后公告，并更新网关默认配置与开发者文档。开放平台默认配额调整须联席通过后公告；租户侧 SDK 应尊重 Retry-After 退避。
