# 容量规划与成本回收

> 文档编号：`c50-it-capacity` · 领域：it · 语料：corpus-50 · 锚点令牌：`C50-031-CAPACITY`

## 1. 目的与适用范围

本制度规定云主机、容器节点与托管数据库的容量观测、闲置识别与成本回收流程，适用于全体研发、运维及拥有资源账号的业务方。个人电脑与办公外设不在此列，按固定资产制度管理。财务侧成本分摊账单以本制度触发的回收与降配结果为准。

## 2. 术语

| 术语 | 含义 |
|------|------|
| 容量台账 | 云管平台中按项目/环境登记的计算与存储资源清单 |
| 枯枝回收 | 对持续低负载闲置实例发起的停机、降配或下线工单 |
| 护林人 | 各业务线指定的资源 Owner，负责认领与申诉 |
| 保活标签 | 经架构/安全备案、可豁免自动回收的资源标记 |

## 3. 核心锚点

闲置计算资源连续 14 天 CPU < 5% 触发「枯枝回收」工单。

检索锚点令牌：`C50-031-CAPACITY`（评测与抽检用，不得删改）。

## 4. 观测与触发

1. 云管平台按日采集 CPU、内存、磁盘 IOPS；CPU 均值为工作日 08:00–22:00 窗口加权值。
2. 连续 14 个自然日 CPU 均值均低于 5%（且无人工「保活」标签）即自动创建枯枝回收工单，工单号前缀 `DRY-`。
3. 仅内存或磁盘低负载、但 CPU ≥ 5% 的，不触发枯枝回收，改入「瘦身建议」清单，由护林人季度处理。
4. 生产只读副本、灾备热备须打标签 `keep-alive:bc`，豁免自动回收，但仍计入成本分摊。
5. 容器集群按「命名空间稳态 CPU」聚合判定；单 Pod 抖动不单独开枯枝单，连续 14 天命名空间均值 < 5% 时对超配 Request 发起降配建议单。

## 5. 回收流程

1. 工单创建后 T+1 通知护林人与项目经理；3 个工作日内须选择：保留（附业务理由）/ 降配 / 下线。
2. 逾期未响应：非生产环境自动停机；生产环境升级至 SRE 值班经理，禁止静默删除。
3. 选择「保留」须填写预计利用率回升时间，最长备案 60 天；到期仍触发则须总监加签。
4. 下线完成后释放配额回项目池；磁盘默认保留 7 天快照窗口，护林人确认后销毁。
5. 财务按月出具分摊账单，枯枝回收节省额在账单中单列「DRY 节降」。

## 6. 规划与预算

- 新项目申请计算资源须在容量台账登记峰值与稳态预估；稳态预估偏差超过 40% 的，次季度核减默认配额。
- 大促、发布演练可申请「临时扩容券」，最长 14 天，到期自动回收，不计入枯枝统计窗口。
- 跨云迁移期间，源端实例可申请冻结枯枝检测，须架构组备案，冻结最长 45 天。
- 年度容量规划会于每季度首月召开，护林人须提交闲置率与节降目标。

## 7. 例外

- 批处理仅周末跑批的实例：可改用「定时启停」策略，启停脚本生效后退出枯枝队列。
- GPU 训练节点按队列空闲率判定，不以 CPU < 5% 为唯一条件。
- 安全隔离沙箱、漏洞扫描靶机：标签 `keep-alive:sec`，豁免自动停机。
- 监管要求保留的取证环境：合规书面确认后豁免，并每季度复核必要性。

## 8. 禁止与处罚

禁止伪造负载、用空转脚本抬高 CPU、擅自删除枯枝工单或去掉他人护林人标签。查实后按变更违规记入个人质量档案，情节严重的收回云账号自助权限，并追溯当月成本至责任项目。

## 9. FAQ

**Q1：14 天是否含周末？**  
A：含。按自然日连续计数，周末低负载同样计入。

**Q2：CPU 偶发尖峰能否打断连续计数？**  
A：单日均值 ≥ 5% 即重置连续闲置计数；瞬时尖峰不计入日均值抬升。

**Q3：枯枝回收会直接删盘吗？**  
A：不会。默认先停机保留磁盘 7 天，护林人确认后再销毁卷。

**Q4：谁能打保活标签？**  
A：护林人申请，架构组或安全组审批后生效；业务经理单独标注无效。

**Q5：数据库实例怎么算 CPU？**  
A：托管库取主实例 CPU；只读副本单独计量，热备带 `keep-alive:bc` 豁免回收。
## 10. 成本分摊与申诉

枯枝回收产生的节降记入项目成本中心，护林人可在账单出具后 10 个工作日内申诉计量错误（如保活标签审批延迟）。申诉须附云管截图与工单号，架构组 5 个工作日内裁定；裁定前账单按原值入账，裁定后差额下月冲正。跨项目共用实例须事先在容量台账拆分比例，否则默认按护林人所在项目 100% 承担。

## 11. 附则

本制度由基础设施与架构组解释，自发布之日起施行。与《生产变更与发布窗口》《业务连续性与灾备切换》交叉时，保活豁免以本制度标签规则为准，变更窗口仍须遵守变更制度。
