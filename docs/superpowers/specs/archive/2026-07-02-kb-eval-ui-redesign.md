# 知识库工作台 · 评测 Tab 设计

> **状态**：已实施（2026-07-03）  
> **父文档**：[2026-07-01-rag-studio-v2-design.md](./2026-07-01-rag-studio-v2-design.md)  
> **索引**：[docs/rag/README.md](../../../rag/README.md) · **未实现**：[backlog.md](../../../rag/backlog.md)  
> **原则**：两 Tab + 记录内嵌；Badcase 并入评测集；内置评测集 SSOT 在 `docker/mysql/init/`

---

## 1. 目标

| 目标 | 说明 |
|------|------|
| 两个 Tab | **运行评测** / **评测脚本**；记录在运行页内嵌 + 抽屉 |
| 人性化 | 用户向文案、卡片摘要、可点击记录、引导说明 |
| 少维护 | Badcase 不再独立表/Tab；Profile 拆为多个内置评测集；种子只在 `docker/` |
| 对齐现有页 | 运行页学 **检索调试**；脚本页学 **Skills 管理**；记录页学 **版本历史列表** |

---

## 2. 信息架构（定稿）

```
评测（KbEvalPanel）
├── Tab 1 · 运行评测     — 选集 → 运行 → 内嵌评测记录 + 右侧抽屉报告详情
└── Tab 2 · 评测脚本     — 管理评测集（条目、YAML/Python、新建/导入）
```

**删除**：独立 Badcase Tab、Profile 下拉、suiteKey 暴露给运营用户、独立「评测记录」顶层 Tab。

**统一概念**：对外只称 **评测集**（= 一组 Query + 期望文档；技术实现可为 YAML 或 Python）。

## 3. Tab 1 · 运行评测

### 3.1 用户心智

> 「用右上角当前应用配置，在选定的评测集上跑一遍检索质量检测。」

主路径 **2 步**：选评测集 → 点「运行评测」。

### 3.2 布局（参考 KbDebugPanel）

```
┌─ 运行评测 ─────────────────────────────────────────────────┐
│ ℹ 将使用右上角「应用配置」中的检索参数进行评测                  │
│                                                              │
│ 评测集  [标准回归（123 条）        ▼]     [▸ 高级选项]         │
│                                                              │
│         [ 运行评测 ]                                          │
│                                                              │
│ ┌─ 本次运行 ─────────────────────────────────────────────┐  │
│ │ 排队中 / 运行中 ████████░░  38/123 条                    │  │
│ └────────────────────────────────────────────────────────┘  │
│                                                              │
│ ┌─ 评测结果 · 任务 #128 ──────────────────────────────────┐  │
│ │ [Recall@5 0.9821] [MRR 0.9102] [门禁 通过]               │  │
│ │ 视图：[概览] [失败样本] [调参建议]                        │  │
│ │ ─────────────────────────────────────────────────────  │  │
│ │ （概览）R@3 / R@5 / R@10；耗时；评测集名称                 │  │
│ │ （失败）表格：问题 | 期望文档 | 实际命中 Top5              │  │
│ │ （建议）[生成建议] [应用到参数草稿] + 诊断文案              │  │
│ └────────────────────────────────────────────────────────┘  │
└──────────────────────────────────────────────────────────────┘
```

### 3.3 控件说明

| 控件 | 文案 | 行为 |
|------|------|------|
| 评测集下拉 | `displayName（N 条）` | 内置集 + 用户自定义集；默认 `标准回归` |
| 高级选项（折叠） | 默认收起 | 仅「检索策略覆盖」（空=跟配置） |
| 运行评测 | 主按钮 round primary | 禁用：无 kb / 配置不可评测 |
| 结果视图切换 | 分段按钮（同 Debug 页 view-switch） | 概览 / 失败样本 / 调参建议 |

### 3.4 不再出现

- ~~评测 Profile~~ → 用不同内置评测集代替（标准回归 / 难例对抗 / 冒烟门禁）
- ~~评测记录~~ 嵌在本 Tab → 移到 Tab 3
- ~~「设为运行脚本」~~ → 下拉即所选

### 3.5 与评测记录联动

运行完成后，同页下方展示评测记录列表；点击行打开右侧抽屉查看报告详情（无需切换 Tab）。

## 4. Tab 2 · 评测脚本

### 4.1 用户心智

> 「管理所有评测集：看内置标准集、编辑本库自定义集、维护难例条目。」

**一个 Tab 管全部资产**：脚本元数据、评测集 YAML、难例（queries 中的一行）、Python 扩展脚本。

### 4.2 布局（参考 SkillsView 左列表 + 右详情）

```
┌─ 评测脚本 ─────────────────────────────────────────────────┐
│ ┌ 评测集列表 260px ──┐ ┌ 详情 ────────────────────────────┐ │
│ │ 🔍 搜索评测集…      │ │ 标准回归              [内置][只读] │ │
│ │ [+ 新建评测集]      │ │ 123 条 · YAML · 标准检索回归用例   │ │
│ │                     │ │ ───────────────────────────────  │ │
│ │ ● 标准回归  [内置]  │ │ 视图：[条目列表] [YAML 源码]      │ │
│ │   难例对抗  [内置]  │ │                                  │ │
│ │   冒烟门禁  [内置]  │ │ （条目列表 — 人性化表格）          │ │
│ │   本库自定义        │ │ # | 问题 | 期望文档 | 标签 | 操作  │ │
│ │                     │ │ 1 | 年假几天 | 考勤制度 | — | 删   │ │
│ │                     │ │ [+ 添加条目]  ← 原 Badcase 入口    │ │
│ │                     │ │                                  │ │
│ │                     │ │ （YAML 源码 — monospace 编辑器）   │ │
│ │                     │ │ [保存] [上传文件] [复制为新集] [删] │ │
│ └─────────────────────┘ └──────────────────────────────────┘ │
└──────────────────────────────────────────────────────────────┘
```

### 4.3 评测集列表卡片

每条显示：

- **主标题**：`displayName`（非 suiteKey）
- **标签**：`内置` / `本库`
- **副文案**：`123 条 · YAML` 或 `Python 脚本`

选中态：内描边 ring（与 Skills / Codex 规范一致）。

### 4.4 详情区 · 双视图

| 视图 | 适用 | 说明 |
|------|------|------|
| **条目列表** | declarative 评测集 | 将 YAML `queries[]` 解析为表格；运营无需读 YAML |
| **YAML 源码** | declarative | 高级用户 / 批量编辑；与列表双向同步（保存时合并） |

Python 类评测集：仅 **源码** 视图 + 说明「输出须为 JSON metrics」。

### 4.5 Badcase 融合（无独立概念）

| 原 Badcase | 新做法 |
|------------|--------|
| Badcase Tab | **本库自定义**评测集内的「添加条目」 |
| 检索调试收集难例 | 结果行 **[加入评测集]** → 选目标集（默认本库自定义） |
| `badcase` 表 + export API | 废弃；条目即 `queries[]` 一行，`category: badcase` 可选 |
| 导出为脚本 | 删除；保存评测集即可在 Tab 1 选用 |

**添加条目**表单（单行）：

- 问题（必填）
- 期望文档（doc_id，逗号分隔，可联想本库文档）
- 备注（选填）

### 4.6 内置评测集

| suiteKey | 显示名 | 说明 |
|----------|--------|------|
| `sunshine-regression` | 标准回归 | 全量回归用例（不含 adversarial） |
| `sunshine-adversarial` | 难例对抗 | 对抗/难例子集 |
| `sunshine-smoke` | 冒烟门禁 | 发布/切换配置用（约 50 条） |

内置集：**只读**；提供 **「复制为本库自定义集」**。

每库自动有一个可编辑集：`{kbId}-custom`（显示名：`{知识库名} 自定义`），初始 `queries: []`。

### 4.7 新建评测集

弹窗字段：

- **名称**（必填）→ 自动生成 `suiteKey`（slug）
- **类型**：评测条目（YAML）/ Python 脚本

不提供 suiteKey 手填（减少理解成本）。

## 5. 评测记录（内嵌运行页 + 抽屉）

> 非独立顶层 Tab；与 Tab 1 同屏，筛选/刷新/报告详情见 `KbEvalHistoryTab` + `KbEvalReportDrawer`。

### 5.1 用户心智

> 「查以前跑过的评测，对比结果，点开看失败样本。」

### 5.2 布局

```
┌─ 评测记录 ─────────────────────────────────────────────────┐
│ 筛选：[全部配置 ▼] [全部状态 ▼] [全部评测集 ▼]   共 42 条    │
│                                                              │
│ ┌──────────────────────────────────────────────────────────┐│
│ │ 任务    评测集        配置版本   状态    R@5    时间        ││
│ │ #128   标准回归      v3 已发布  通过   0.982  07-01 21:00 ││ ← 可点击
│ │ #127   本库自定义    v2 草稿    失败   0.801  07-01 18:22 ││
│ └──────────────────────────────────────────────────────────┘│
│                                                              │
│ ┌─ 报告详情（选中行后下方展开）────────────────────────────┐  │
│ │ 任务 #128 · 标准回归 · hybrid+rerank                      │  │
│ │ [R@5] [MRR] [门禁]   视图：[概览][失败样本][调参建议]      │  │
│ │ （复用 Tab 1 的 KbEvalResultView 组件）                    │  │
│ └──────────────────────────────────────────────────────────┘  │
└──────────────────────────────────────────────────────────────┘
```

### 5.3 筛选器（人性化文案）

| 筛选项 | 选项 |
|--------|------|
| 配置范围 | 全部配置 / 仅当前应用配置 |
| 状态 | 全部 / 已完成 / 失败 / 运行中 |
| 评测集 | 全部 / 各 displayName |

### 5.4 列表行

- 点击行 → 下方展开报告（不跳 Tab）
- 状态 Tag：`通过`（绿）/ `未通过`（红）/ `运行中` / `失败`
- R@5 低分时数字标红

### 5.5 空态

「暂无评测记录 — 前往 **运行评测** 开始第一次检测」+ 按钮跳转 Tab 1。

## 6. 数据与种子（后端约束）

### 6.1 存储

| 层 | 内容 |
|----|------|
| MySQL `eval_suite` | 元数据：suiteKey、displayName、kind、itemCount、contentRef、hooks |
| MinIO | `rag-eval/{tenant}/{suiteKey}/suite.yaml` 或 `suite.py` |

### 6.2 内置种子 SSOT：`docker/` only

```
docker/
├── mysql/init/10-sunshine-rag-eval-suite.sql   # eval_suite 元数据 INSERT
└── minio/init/rag-eval/default/
    ├── sunshine-regression/suite.yaml
    ├── sunshine-adversarial/suite.yaml
    └── sunshine-smoke/suite.yaml
```

`init-minio.sh` 扩展：创建 `sunshine-rag` bucket 并上传上述 YAML。

**去除**：

- `EvalSuiteService.seedGoldenSetOnStartup()`
- Flyway 数据种子
- Nacos `rag.eval.golden-set-path`
- 运行时读 `docs/rag/golden-set.yaml`
- `badcase` 表及 API

### 6.3 API 调整（最小）

| API | 变更 |
|-----|------|
| `POST /eval/run` | 仅 `suiteKey`；去掉 `suite`（profile） |
| `GET/POST /eval/suites` | 保留；POST 支持整包 YAML 更新 |
| **新增** `POST /eval/suites/{key}/queries` | 添加/更新/删除单条 query（供条目列表 UI，避免手改 YAML） |
| `badcases/*` | 废弃 |

### 6.4 发布门禁

`ConfigVersionService` smoke 固定跑 `sunshine-smoke` 评测集。

## 8. 文案对照表

| 旧文案 | 新文案 |
|--------|--------|
| 评测脚本 Tab | **评测脚本**（管理评测集） |

## 9. 检索调试联动

`KbDebugPanel` 每条命中或空结果行增加：

**「加入评测集」** → 小弹窗：目标集（默认 `{kbId}-custom`）+ 期望文档 → 调 `POST .../queries` → Toast「已加入 xxx 自定义评测集」。

## 10. 实施顺序

| 阶段 | 内容 |
|------|------|
| P0 | Docker 种子（3 内置集）+ 去 Java seed / badcase 表 |
| P1 | 两 Tab 壳 + 运行页（含内嵌记录）+ `KbEvalResultView` |
| P2 | Tab2 脚本页（列表 + 条目表 + YAML）+ queries API |

| P4 | 清理废弃组件/常量/`evalConstants` Profile |

---

## 11. 验收标准

1. 评测 Tab 仅 **2 个子 Tab**（运行 \| 脚本），记录内嵌运行页
2. 新用户：Tab1 选「标准回归」→ 运行 → 看到结果，**≤3 次点击**
3. Tab2 可 **表格方式** 添加难例，无需理解 YAML
4. 运行页内可 **筛选并点开** 历史报告（抽屉），失败样本可读
5. 内置评测集条目来自 **MySQL 种子**（`10/11-sunshine-rag-eval-suite*.sql`）
6. 无独立 Badcase Tab/表

---

## 12. 与 V2 父 spec 关系

- 保留 MySQL + MinIO 存储模型
- 收敛：Badcase → 评测集条目；Profile → 多内置集
- 种子 SSOT 从「多入口」改为 **`docker/` only**
